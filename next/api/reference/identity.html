End the current session server-side (REQ-164 AC1, ADR-037) ​

POST /auth/logout · logout

Revokes the current session and its refresh tokens; the response carries OEA-Purge-Local-Data: session-ended so that the Electron client clears its offline cache. For OIDC sessions the response includes the IdP end-session URL if the provider supports RP-initiated logout.

Local login of the system admin account and of persons (US-013 AC2, US-011, ADR-042) ​

POST /auth/local/login · localLogin

Login name and password. A loginName containing @ is the e-mail address of a person; it is accepted only while the operator has switched on password login of persons (oea.auth.person-password.enabled), for persons in status invited or active with an unexpired password. The first login of an invited person makes it active. A person without an active TOTP credential gets a session that is not second-factor-verified (SoD-8); a person with one gets 401 with problem type urn:oea:problem:second-factor-required and a loginTransaction, as below, and is activated only after the TOTP step (REQ-010). A temporary or expired password yields requiredAction: change-password (REQ-173 AC2), after the TOTP step if there is one (REQ-031 AC8).

For the system admin account: during the setup phase (ADR-042) a correct password creates the session. Afterwards the response is 401 with problem type urn:oea:problem:second-factor-required and a loginTransaction, which POST /auth/local/login/totp completes with a TOTP code. Wrong login name and wrong password produce the same 401 urn:oea:problem:invalid-credentials; repeated failures are throttled (REQ-168). Every failed login runs one password hash verification, so response times reveal no account (REQ-006). Protected by an origin check (REQ-187).

Access: public – no authentication

Second step of the local login with a TOTP code (REQ-171, REQ-010) ​

POST /auth/local/login/totp · localLoginTotp

Completes a login transaction of the system admin account or of a person with a TOTP code of any active TOTP credential of the owner (REQ-030). The session is second-factor-verified. Five wrong codes invalidate the transaction (REQ-168 AC2); a code is never accepted twice (REQ-170). Audited as auth.login with method password-totp.

Start the OIDC login through a provider (US-001, REQ-166) ​

GET /auth/oidc/{providerId}/start · startOidcLogin

Redirects the browser to the provider's authorization endpoint (authorization code flow with PKCE S256, state and nonce) and sets the login cookie __Host-OEA_LOGIN (HttpOnly, Secure, Path=/, SameSite=Lax, 10 minutes), which binds the running login to the browser. A provider that is unknown, disabled or unreachable redirects to <public URL>/login?error=provider-unavailable.

Access: public – no authentication

Callback of the OIDC login (US-001, REQ-004, REQ-166) ​

GET /auth/oidc/callback · completeOidcLogin

Redirect URI <public URL>/api/v1/auth/oidc/callback. Accepts the callback only with the state of a running login and the matching login cookie (single use), redeems the code with the PKCE verifier, validates the ID token, finds the person through the binding (iss, sub) and creates the session cookie __Host-OEA_SESSION. Every failure redirects to <public URL>/login?error=login-failed without revealing the reason; the reason is audited (REQ-005, REQ-006).

Change the own local password (REQ-173 AC2, UC-03) ​

POST /me/password · changeOwnPassword

For persons with a local password and the system admin account. Requires the current password; the new one must differ from it and satisfy the password policy including its history (REQ-028), otherwise 422 with problem type urn:oea:problem:password-policy-violation whose invalidFields name every unmet rule (minLength, maxLength, requireUppercase, requireLowercase, requireDigits, requireSpecialChars, historyCount). Stores it as self-set without expiry, lifts requiredAction: change-password of the session and revokes every other session of the principal. A wrong current password → 403 with problem type urn:oea:problem:invalid-credentials, counted by the login throttling (REQ-168). Audited as auth.password-changed.

Access: any authenticated principal

Suggest a password for the own change (US-026, REQ-027) ​

POST /me/password/suggestion · suggestPassword

For principals with a local password. Generates a password with a cryptographically secure random source from the printable ASCII characters that satisfies the password policy; it is not stored. Allowed while the session must change its password. A policy that cannot be satisfied → 409 with problem type urn:oea:problem:password-policy-unsatisfiable.

Start the enrollment of a TOTP second factor (REQ-171, REQ-022, ADR-042) ​

POST /me/second-factors/totp · startTotpEnrollment

For the system admin account and for persons with a local password; other principals get 403. Requires an authentication within the last 5 minutes (REQ-172), otherwise 401 with problem type urn:oea:problem:reauthentication-required. Returns the secret once; the credential stays pending until confirmed (10 minutes). Several active TOTP credentials per owner are allowed (REQ-030); a blank label becomes Authenticator app (YYYY-MM-DD).

POST /me/second-factors/totp/{credentialId}/confirm · confirmTotpEnrollment

Activates the credential and marks the current session as confirmed with a second factor; an audit event auth.factor-added is written (REQ-172 AC3). A wrong code (400) keeps the enrollment pending; an unknown, foreign or expired enrollment is answered with 404. Both failures are audited as auth.factor-enrollment-failed (REQ-025).
