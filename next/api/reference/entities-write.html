Entities – Write ​

Operations of the tag Entities – Write implemented in this release. Generated from api/openapi.yaml; planned operations are not listed.

Delete an entity from the repository (US-074, REQ-146, UC-10) ​

DELETE /entities/{id} · deleteEntity

Soft-deletes an element entity or a connection (ADR-019). The entity, its children on all levels (at most 10) and every active connection with the entity or one of the children as endpoint are deleted in one transaction, with one time and actor; the cascade always applies. Deleted entities leave catalogs and baselines, their history and audit trail stay, and their external IDs stay reserved (#70). The entity itself has no cascade origin; the others record it as the entity whose deletion took them along, the reason cascade: entity <id> deleted and the audit event entity.cascade-deleted; the entity is audited as entity.deleted. Versions do not change. The answer lists every deleted ID, the entity first, then children and connections, so that a client can remove them.

A connection is deleted alone. A structuring aid (its own operation deleteStructuringAid moves the children to the top level) and an automatic composition connection (changing the parent removes it) give 422 naming entityId.

If-Match with the current version is required: 428 without it, 412 stale-version when the entity changed meanwhile. An open issue of a solution on the entity, a child or a connection gives 409 entity-blocked. Deleting a set that holds a connection of a type used as scopingConnectionType also needs visibility-scope:assign (REQ-161). Deltas modified and retiring of active solutions on the deleted entities become deletion conflicts of those solutions (previewEntityDeletion names them beforehand).

Access: permission entity:delete; additionally visibility-scope:assign when the deleted set holds a connection of a type used as scopingConnectionType

Restore a deleted entity with its cascade (REQ-159, ADR-019) ​

POST /entities/{id}/undelete · restoreDeletedEntity

Undeletes an entity (the path /entities/{id}/restore restores a version). The entity and what its deletion took along are restored in one transaction: its descendants with the same cascade origin and deletion time, and the connections of that cascade with an endpoint among them, whose endpoints are active afterwards. Versions do not change, and each restored entity is audited as entity.undeleted. An entity deleted before the cascade origin existed is restored alone. Rows deleted earlier or by another deletion are never restored, even in the same instant.

A connection whose other endpoint is still deleted (endpoint-deleted), or an automatic composition connection whose child no longer has that parent (parent-changed), stays deleted and is listed in notRestored. An element entity whose parent is deleted, or whose subtree would end more than 10 levels below the root, is placed at the top level as a new version (audited as entity.parent-changed) and listed in movedToTopLevel. A connection restored directly needs both endpoints active (409 connection-not-restorable, extension member reason endpoint-deleted).

If-Match with the version of the deleted entity is required: 428 without it, 412 stale-version when it differs. Restoring a set that holds a connection of a type used as scopingConnectionType also needs visibility-scope:assign (REQ-161). The version restore (restoreEntity) of a deleted entity answers 409 entity-deleted: undelete first.

Access: permission entity:restore; additionally visibility-scope:assign when the restored set holds a connection of a type used as scopingConnectionType

GET /entities/deleted · listDeletedEntities

Create/update entities and connections in batch ​

POST /entities/batch · batchWriteEntities

Writes up to 500 entities and 500 connections in one request. The preferred endpoint for external systems with strategy: upsert (ADR-026). ?dryRun=true → validation without persisting. Connections are written after the entities; their endpoints are checked against the connection metatype (codes SOURCE_REQUIRED, SOURCE_AMBIGUOUS, SOURCE_NOT_FOUND, SOURCE_NOT_ALLOWED, the same for TARGET_, METATYPE_NOT_CONNECTION and ENDPOINT_CHANGE_NOT_SUPPORTED). An endpoint that is a connection that itself starts or ends at a connection is rejected with CONNECTION_DEPTH_EXCEEDED on the endpoint field (ADR-010). An update of an entity with an open issue of a solution fails with OPEN_ISSUES (US-153 AC1). Not supported yet: dryRun=true (US-141 AC3) is rejected with 422; parentId and lifecycle are item errors. X-Agent-Id is stored only as the informational audit field agent_label (ADR-033 §7). A batch with a connection of a metatype that is the scopingConnectionType of a property definition needs visibility-scope:assign; without it the whole batch is rejected with 403 (REQ-161). A value of a role-restricted property, set or removed, needs one of its write roles, and a value of a connection-scoped property an existing entity in the writer's scope; otherwise the whole batch is rejected with 403 (REQ-126, REQ-127). A property not named keeps its value.

An item whose external ID belongs to a deleted entity is rejected with EXTERNAL_ID_DELETED, and an atomic batch changes nothing. Only an upsert item of a writer who also holds entity:restore restores the entity with its cascade and then updates it (restored: true, audited as entity.undeleted, #70); create-only and skip-existing never restore, and the external ID is never reused by a new entity. A restored set that holds a connection of a scoping type needs visibility-scope:assign (403). A connection item is restored only with active endpoints.

Access: permission entity:write; additionally visibility-scope:assign when a connection of a type used as scopingConnectionType is written; additionally entity:restore when an upsert item names the external ID of a deleted entity

Create connection between two entities ​

POST /connections · createConnection

Creates a connection, an entity of a connection metatype with a source and a target (US-036, ADR-010). Source and target are referenced by internal ID or externalId; their metatypes must be allowed by the connection metatype (subtypes included) and cannot change afterwards. Without name the connection is named <source name> → <target name>. Properties are checked as for entities. A connection of a metatype that is the scopingConnectionType of a property definition also needs visibility-scope:assign, otherwise 403 (REQ-161). A value of a role-restricted property needs one of its write roles, otherwise 403 (REQ-126); a value of a connection-scoped property cannot be set on creation, because the connection is not yet in the writer's scope (403, REQ-127). An endpoint that is a connection must itself run between elements: a connection at a connection that itself starts or ends at a connection is rejected with 422 CONNECTION_DEPTH_EXCEEDED naming the endpoint, whatever the endpoint lists of the connection metatype allow (ADR-010, US-064 AC4).

Access: permission entity:write; additionally visibility-scope:assign when a connection of a type used as scopingConnectionType is written

Set or clear the parent of an element entity (US-135, UC-13) ​

PUT /entities/{id}/parent · setEntityParent

Places an element entity under another element entity, or clears the parent with parentEntityId: null (US-135, US-136; REQ-141, REQ-142, ADR-021). The change is versioned like other entity changes: it writes the next version of the child, whose history, versions and diffs show the system field parentEntityId ("Parent") by name, and the audit event entity.parent-changed; the parent keeps its version. A restore does not restore the parent. Setting the parent the entity already has changes nothing and writes no version and no event (composition.reason unchanged).

The parent is another element entity that is not deleted; connections have no parent and are no parent. A parent that is the entity itself, one of its descendants, a connection, deleted or unknown, or a subtree that would end more than 10 levels below the root (the root level is level 1) gives 422 naming parentEntityId; a connection as child gives 422 naming entityId.

When neither entity is a structuring aid and the connection metatype marked as composition (isComposition) allows the metatype of the parent as source and that of the child as target, a connection of it from the parent to the child is created in the same transaction and marked autoCreated; otherwise only the parent is stored and composition.reason says why. Clearing or changing the parent soft-deletes the connection auto-created for the previous parent (removedConnectionId), if it is not deleted yet; a connection written by other means stays.

If-Match with the current version of the child is required: 428 without it, 412 stale-version when the entity changed meanwhile. An entity with an open issue of a solution gives 409 entity-blocked (US-153). Needs entity:write.

Access: permission entity:write

Create a structuring aid (US-136, UC-13) ​

POST /structuring-aids · createStructuringAid

Creates a structuring aid, a purely navigational grouping (US-136, REQ-141): an entity of the built-in metatype "Structuring aid" with isStructuralGrouper set, at the root level or under parentEntityId. It has no properties, no connections and is not part of a solution. The name is trimmed and has 1–255 characters, the description at most 2000. The parent is checked as for setEntityParent (an element entity that is not deleted, at most 10 levels deep); an invalid one gives 422 naming parentEntityId, an invalid name or description 422 naming name or description; a parentEntityId below 1 gives 422 naming parentEntityId too. Writes version 1 and the audit event entity.created. Needs entity:write.

Delete a structuring aid (US-136, UC-13) ​

DELETE /structuring-aids/{id} · deleteStructuringAid

Soft-deletes a structuring aid (ADR-019). Its children move to the root level, each with a new version (entity.parent-changed), and none of them is deleted; the aid is deleted with the audit event entity.deleted (cause structuring-aid-deleted), all in one transaction. An entity that is no structuring aid gives 422 naming entityId. If-Match with the current version of the aid is required (428, 412). The aid or one of its children with an open issue of a solution gives 409 entity-blocked. Needs entity:write and entity:delete.

Access: permission entity:write, entity:delete
