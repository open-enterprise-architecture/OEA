Navigation tree (US-054, SCR-055, SCR-010/011) ​

GET /views/explorer · getExplorerView

The navigation tree from the root folder "Repository", with all folders and their entries – catalogs, element entities and solutions (US-054, US-095, REQ-050, REQ-095, REQ-096). Solution browser, top level (US-132, US-133, SCR-055) ​

GET /views/browser · getBrowserView

The top level of the solution browser (REQ-138, REQ-140): the counts of the current state, the plateaus with status transition or target in the order of the plateau overview (validFrom, then name; the baseline and realized plateaus have no node), each with its active solutions, and the active project solutions. Active means a status other than implemented and archived. Solutions come sorted by name, case-insensitively. The counts of the current state are the element entities and connection entities that are not deleted and the catalogs the caller sees (instance catalogs and the caller's own personal ones); the count of a solution is the number of its deltas. The categories themselves are read with listBrowserItems. Read only, not audited.

Contents of a category of the solution browser (US-132, US-133, SCR-055) ​

GET /views/browser/items · listBrowserItems

One page of one category of the browser, ordered by name (case-insensitive), then by ID. scope current-state takes solutionId never and the categories components (element entities that are not deleted), connections (connection entities that are not deleted) and catalogs (the catalogs the caller sees); scope solution needs solutionId and has the category components only, which lists the deltas of the solution (new, modified, retiring), also for an implemented or archived solution. A delta modified or retiring shows name and metatype of its entity, a delta new those of the delta. A pageSize outside 1–200, a page below 0, a missing or unknown scope or category and a solutionId that is no UUID answer 400. Answers 422 (problem type urn:oea:problem:validation-failed) with invalidFields solutionId when it is missing for solution or given for current-state, and category for connections or catalogs with solution; 404 for an unknown solution. Read only, not audited.

"Components" of current-state list the root level: the element entities without a parent, or whose parent is deleted (US-135). With parentEntityId the page lists the children of that element entity instead; this needs scope current-state and category components (else 422 naming parentEntityId), a value below 1 gives 400, and an unknown or deleted entity, or a connection, gives 404. Each entity item carries its childCount, whether it is a structuringAid and its version.

Access: permission entity:read

Create a folder in the navigation tree (REQ-094, UC-13) ​

POST /tree-nodes · createTreeNode

Creates a folder under an existing folder. The name is trimmed, has 1–255 characters without control characters and is unique among its siblings regardless of case (BR-01). A folder is at most 10 levels below the root; the tree has at most 500 folders. The new folder goes after its siblings (REQ-096). Validation errors answer 422 with invalidFields name or parentId (an unknown parent). Writes the audit event tree-node.created. Every write of the tree needs entity:read in addition, because it answers with the tree and the names of its entries.

Access: permission viewpoint:manage, entity:read
