Setup ​

Operations of the tag Setup implemented in this release. Generated from api/openapi.yaml; planned operations are not listed.

Whether the instance still needs its local bootstrapping (US-013) ​

GET /setup/status · getSetupStatus

Public, because no principal exists before the bootstrapping. Returns only whether setup is required – no token, account or instance data.

Access: public – no authentication

Responses ​

StatusDescriptionProblem types
200Setup status–
429Rate limit or throttling exceeded (REQ-186, REQ-168), problem type urn:oea:problem:too-many-requests; Retry-After gives the seconds until the next request is accepted. Nothing was processed.urn:oea:problem:too-many-requests

Local bootstrapping – create the system admin account and the instance slug (US-013) ​

POST /setup · completeSetup

Public, but only effective with the one-time setup token, which the backend writes to a file inside its container and never returns or logs (REQ-017, REQ-175). Exactly one bootstrapping can succeed per instance (REQ-015); every attempt is audited as system.bootstrapped or system.bootstrap-rejected (REQ-016). The request body is never logged.

Access: public – no authentication

Request body ​

  • application/json: SetupRequest
