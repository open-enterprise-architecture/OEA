Change history of an entity (SCR-026) ​

GET /entities/{id}/history · getEntityHistory

The versions of the entity, newest first (US-098, REQ-098, UC-14). Source: entity_version_headers with the changed fields from entity_system_field_history and entity_property_value_history (ADR-022). A version names its changed fields without values; values come from getEntityVersion and compareEntityVersions. Version 1 is the creation and has no changed fields.

A changed property the caller may not read (role-restricted without a read role, connection-scoped outside the caller's scope, REQ-160) is listed with restricted: true, or left out when every role of the caller is set to hide for the entity's metatype (/admin/history-visibility). A version whose fields are all left out is still listed. Holders of an override role read every field (REQ-128).

from and to are inclusive; from after to answers 400 naming from. actors and created ignore the filters and the paging. Paging as in the delta list: send nextCursor with page + 1; a cursor of another query answers 400 cursor.

Access: permission entity:read

Complete state of a version (SCR-026) ​

GET /entities/{id}/versions/{version} · getEntityVersion

The complete state of a version of the entity (US-100, REQ-100, UC-14): the system fields and the properties mapped to the entity's metatype at the time of the version (effective date on or before it), including empty ones, plus every property that had a value then. The state is reconstructed from the history tables (ADR-022); nothing is stored per version.

Versions are immutable: PUT and DELETE on this path answer 405 with Allow: GET.

A property the caller may not read is listed with restricted: true and no value, or left out by the history visibility, as in getEntityHistory. A value read only through an override role is audited as property-override-access (channel history).

Access: permission entity:read

Field-by-field diff of two versions (SCR-026) ​

GET /entities/{id}/diff · compareEntityVersions

The fields whose value differs between the state of version from and the state of version to (US-099, REQ-099, UC-14): a net diff, so a field changed and changed back between them is not listed. The diff of a single version N is from=N-1&to=N. from must be at least 1 and before to, otherwise 400 naming from; a version that does not exist answers 404.

Values the caller may not read are redacted or left out as in getEntityVersion.

Preview of a restore (SCR-027, UC-15) ​

GET /entities/{id}/restore · previewEntityRestore

What restoreEntity would do with the same target version (US-101 AC2, REQ-101): the current version and every field whose current value differs from the target version, with both values and whether it would be restored. A field is not restored when the caller may not write it (write-protected, REQ-162), when it is no longer mapped to the metatype (not-mapped) or when the current definition no longer accepts the target value (invalid-value, UC-15 E1). Mandatory and recommended properties that would be empty are warnings, never errors.

A value the caller may not read is redacted (REQ-101 AC5, REQ-160); a property hidden for the caller's roles is left out, and a value read through an override role is audited as property-override-access (channel history). Changes nothing.

Access: permission entity:write, entity:restore

Restore entity (SCR-027, UC-15) ​

POST /entities/{id}/restore · restoreEntity

Restores an entity in full to an earlier version (US-101, US-102, US-103, REQ-101 to REQ-103). Name, description, the logical flag and every restorable property get the values of the target version; a property empty in the target version is removed. The ID, the metatype, the endpoints of a connection and the creation fields never change. Fields are classified as in previewEntityRestore; fields not restored keep their current value and are listed in notRestored.

The restore writes one new version with restoredFromVersion and the reason; the version before it stays unchanged in the history as the state before the restore (ADR-022). An empty mandatory property is afterwards marked as missing. Entity, version and the audit event entity.restored are written in one transaction.

If-Match with the current version is required: 428 without it, 412 stale-version when the entity changed meanwhile. A restore whose restorable fields all have their target value already gives 422 urn:oea:problem:nothing-to-restore.

With fields, the restore is partial (UC-16, US-104 to US-106): only the selected fields are restored, selected fields that cannot be restored are listed in notRestored, and the new version records restoredFields. An empty selection or a key that is not a differing field gives 422 validation-failed naming fields.

Access: permission entity:write, entity:restore
