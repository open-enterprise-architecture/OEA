Set the initial password of a person (US-023, REQ-024) ​

POST /admin/persons/{personId}/password · setInitialPassword

Only while password login of persons is possible (permitted by the operator and personPasswordLogin of the password policy on). The password is entered, or generated with generate: true (REQ-027); a generated password is returned this once. Stores it as argon2id with origin initial; it expires after oea.auth.person-password.temporary-password-validity (default 72 h) and must be changed at the first login (REQ-173 AC1/AC2). The password is never logged. Audited as person.password-set.

  • Person already has a password → 409 with problem type urn:oea:problem:password-already-set; password login of persons off → 409 (conflict)
  • Own person → 403 with reason: self-administration (SoD-1)
  • Service account, person not invited/active, neither or both of password and generate: true → 422
  • Entered password violates the password policy → 422 with problem type urn:oea:problem:password-policy-violation

Reset the local password of a person (US-030, REQ-031) ​

POST /admin/persons/{personId}/password/reset · resetPersonPassword

Revokes the person's active password, sets a generated temporary password with origin admin-reset and the expiry of oea.auth.person-password.temporary-password-validity, returns it this once, revokes all sessions of the person (reason password-reset) and requires the password change at the next login (REQ-173 AC2), in one transaction. Audited as person.password-reset without the password.

  • Own person → 403 with reason: self-administration (SoD-1)
  • Target holds an admin-class permission through a local role assignment and the caller is not the system admin account → 403, audited as authz.denied (REQ-031 AC9, REQ-173 AC3)
  • Person without a local password, or password login of persons not possible → 409
  • Service account → 422

Change the status of a person (UC-23 A2, US-148) ​

POST /admin/persons/{personId}/status · changePersonStatus

Transitions active ⇄ inactive and invited/active/inactive → offboarded. Leaving active or invited revokes all sessions of the person at once (REQ-164); offboarded also revokes every local role assignment (audited as role.revoked), while inactive keeps them. Audited as person.status-changed.

  • Own status → 403 with reason: self-administration (SoD-1)
  • Another transition, an unchanged status, or offboarded → invited while the reactivation of offboarded persons is off → 409 with problem type urn:oea:problem:invalid-status-transition
  • Last usable path to system-admin → 409 with problem type urn:oea:problem:last-admin-path (SoD-7)
  • Service account → 422 (status changes of service accounts follow with US-142)
