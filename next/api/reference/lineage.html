Lineage ​

Operations of the tag Lineage implemented in this release. Generated from api/openapi.yaml; planned operations are not listed.

Data lineage of a data object or a system (UC-08, US-065, REQ-062) ​

POST /views/lineage/query · queryLineage

Walks the active data flows from a start element: from a data object over the flows that carry it, from a system hop by hop. direction is downstream, upstream, both (the default, the union of both walks) or impact (downstream with impact true on each node). maxDepth is 1 to 100 (default 50); at most 5000 nodes and 10000 edges are returned, truncated says that there are more; a filter metatypeIds of at most 50 metatypes keeps only the nodes of them and their subtypes, the edges stay. The tasks of the data associations of a data object join at depth 1, writers upstream and readers downstream, when the data-input and data-output parts of the lineage model are set. Deleted entities are left out.

400 for a missing startEntityId, a value out of range, more than 50 metatypeIds or a dataObjectId with a data object start; 404 for an unknown or deleted start; 422 naming metatypeIds for an unknown metatype, dataObjectId for an entity that is no active data object, startEntityId for a connection; 422 LINEAGE_MODEL_INCOMPLETE naming lineageModel when the data-object, data-flow or carries-data part is unset. The only property value returned is "Transformation type" of a data output association, under property visibility (transformationRestricted); a value read through an override role writes one property-override-access event per query with the channel lineage. A POST because the filter list can be long; it only reads and is not audited otherwise.

Access: permission entity:read

Request body ​

  • application/json: LineageQuery
