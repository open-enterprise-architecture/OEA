Create a catalog (US-046, REQ-043) ​

POST /catalogs · createCatalog

Creates a catalog without columns, joins, saved filters and saved views. A catalog with scope instance additionally requires catalog:manage (ADR-032 §3); a catalog with scope personal is visible only to its creator. The name is unique within the instance across both scopes, compared case-insensitively after trimming, and stored trimmed. Writes the audit event catalog.created.

Zugriff: Berechtigung entity:read; zusätzlich catalog:manage, wenn: body field scope is 'instance'

Configure the columns of a catalog (US-047, REQ-044) ​

PUT /catalogs/{id}/columns · updateCatalogColumns

Replaces the column list. Every column names a system field or a property mapped to the primary metatype; at least one column is visible and at most one carries a default sort (422 with invalidFields, e.g. columns[2].propertyDefId). An instance catalog needs catalog:manage; a personal catalog can be changed by its creator only. Without catalog:manage, every catalog except one's own personal catalog is answered with 403, also an unknown one, so that the existence of another person's personal catalog is not revealed. Writes the audit event catalog.columns-changed.

Zugriff: Berechtigung entity:read; zusätzlich catalog:manage, wenn: the catalog has scope 'instance' (another person's personal catalog is never changeable)

Save a filter in a catalog (US-052, REQ-047) ​

POST /catalogs/{id}/filters · addCatalogFilter

Appends a saved filter with a new ID. Every expression names a column key the query of the catalog returns (with every available join), an operator of the column's filter type and a valid value (BR-04, BR-12). A catalog has at most 50 saved filters. Validation errors answer 422 with invalidFields, e.g. name for a blank or taken name, expressions for none or more than 20, or expressions[0].attributePath, expressions[0].operator or expressions[0].value. Permissions as for updateCatalogColumns. Writes the audit event catalog.filter-added.

Zugriff: Berechtigung entity:read; zusätzlich catalog:manage, wenn: the catalog has scope 'instance' (another person's personal catalog is never changeable)

Save a view in a catalog (US-053, REQ-048) ​

POST /catalogs/{id}/views · addCatalogView

Appends a saved view with a new ID. The columns must be primary columns of the catalog, filters and sort columns of the view or of joins, overrides available joins (BR-05, BR-12). With isDefault: true every other view loses its default (BR-06). A catalog has at most 20 views. Validation errors answer 422 with invalidFields, e.g. name, columnOrder[1], filters[0].attributePath, sort or joinModeOverrides[0].joinDefinitionId. Permissions as for updateCatalogColumns. Writes the audit event catalog.view-added.

Query a catalog (US-049, REQ-046, SCR-020) ​

GET /catalogs/{id}/query · queryCatalog

One page of rows: the active entities of the catalog's primary metatype with the values of the catalog's columns. With configured columns (US-047), these are the visible ones in their order and with their labels; a configured property that is no longer available is left out. Without configured columns, the columns are name and, if the primary metatype maps a property named Status with visibility public, that property. Property visibility applies as described at CatalogColumn.readable; a page that returns a value readable only through the override role list writes one property-override-access audit event naming the properties and entities (REQ-128). Soft-deleted entities are not returned (ADR-019). Column keys are the system field (CatalogSystemField) or the sqlColumnName of a property.

sort accepts exactly one {column}:{asc|desc} pair whose column is a sortable key of columns. Without sort the configured default sort applies, else name ascending; rows without a value in the sort column come last, and enum values follow the order of the enum (#65). Sorting applies before paging; a page beyond the last one answers with no rows. A personal catalog of another person is answered with 404, like a catalog that does not exist (ADR-032 §8 L3).

Joins (US-048, US-050): every row carries joinResults per available join. A join's mode is joinMode[{joinId}], else its defaultJoinMode, else the catalog's; the override changes nothing stored. In mode rows every join result is a row of its own (an entity without results keeps one row), paging and totalElements count rows, and a join column ({joinId}.{key}) is sortable; several rows joins give their cross product. An override for an unknown join answers 400 joinMode.

Connection catalogs (US-080): with a connection metatype as primary metatype, the rows are its connections. Columns source.{key} and target.{key} show attributes of the connection's source and target and are sortable like other columns; a deleted endpoint gives empty values. Without configured columns, the columns are source.name, name, target.name and the Status property as above.

Filters (US-051, US-080 AC5, AC6): every filter is {key}:{operator}[:{value}] with a column key of the result (columns, source.{key}, target.{key} or {joinId}.{key} of a join's columns), an operator of the column's filterType and a value; everything after the second colon is the value, a comma-separated list for in/notIn, missing for isNull/isNotNull. At most 20 filters apply; filterMode combines them (default and). A filter on a join column keeps only entries with a matching join result and narrows the join's results to the matching ones, in both modes; with or, an entry passes if any filter holds. Filters apply before sorting and paging, and totalElements counts only the entries that pass. An unknown column, an operator not allowed for the column or an invalid value answers 400 filter.

Views (US-053): with view, the columns are those of the saved view, in its order, and filters and sort may name only these columns and join columns; the view's own filters, join modes and sort are not applied, the client passes them. An unknown view or one with available: false answers 400 view.

Cursor (REQ-071): a page with a following page carries nextCursor. A query with cursor and page returns the rows after the previous page in the same order and with the same total, without skipping rows. A cursor of another query, a changed or unreadable cursor, or a cursor without page answers 400 cursor.

Time limit (REQ-186): a query whose statements take longer than the configured limit (10 seconds by default) is cancelled and answered with 503 query-timeout; the audit event catalog.query-timeout records it.
