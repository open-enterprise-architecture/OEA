# Local Development

Prerequisites, commands and known workarounds for working on OEA outside of CI. The CI workflows in `.github/workflows/` are the reference: a command that passes there and fails locally usually points to one of the workarounds below.

## Prerequisites

| Tool | Version | Used for |
|---|---|---|
| Docker with the Compose plugin, or rootless Podman with its Docker-compatible socket | current | development environment, Testcontainers in the backend tests |
| JDK | 25 (Temurin in CI) | backend build and tests (`./mvnw` downloads Maven itself) |
| Node.js | 24 | frontend build, tests and Storybook |
| Python | 3.12 | repository checks in `scripts/` (standard library only) |
| git | any current | – |

## Development Environment

```bash
scripts/dev.sh            # PostgreSQL, migration step, Keycloak, backend, Vite
scripts/dev.sh reset      # stop and delete the development volumes
python3 scripts/dev_seed.py   # after the setup at /setup: provider, persons and group mappings of the dev realm
```

Addresses, ports and the seed are described in the section "Development" of the [README](../README.md#development). All development credentials are public `*-dev-only` values that the application rejects outside the Spring profile `dev`.

## Builds and Tests

| Area | Command | Notes |
|---|---|---|
| Backend, all tests | `cd backend && ./mvnw verify` | unit and integration tests (surefire), then Cucumber (failsafe, `CucumberIT`); needs a container runtime |
| Backend without Cucumber | `./mvnw verify -DskipITs` | CI job "Backend unit and integration tests" |
| Backend, Cucumber only | `./mvnw verify -Dtest=none -Dsurefire.failIfNoSpecifiedTests=false` | CI job "Backend Cucumber"; one feature with `-Dcucumber.features=classpath:features/<path>.feature` |
| Frontend | `cd frontend && npm ci && npm run type-check && npm test && npm run build` | `npm test` runs the unit tests (jsdom) |
| Story tests | `npm run test:stories` | every Storybook story with its play function and accessibility check in headless Chromium; install the browser once with `npx playwright install --with-deps chromium` |
| Storybook | `npm run storybook` | screen prototypes (ADR-031) at <http://localhost:6006> |
| Contract | `npx @redocly/cli@2.63.0 lint api/openapi.yaml` and `python3 scripts/check_openapi_authorization.py` | CI job "OpenAPI validation" |

## Generated Files

Some files are generated and checked by CI; refresh them in the same pull request as the change that affects them.

| File | Refresh after | Command |
|---|---|---|
| `requirements/traceability.md` | changing use cases, requirements or user stories | `python3 scripts/generate_traceability.py` |
| `THIRD-PARTY-LICENSES.md` | adding or updating a distributed dependency | `./mvnw license:add-third-party` (in `backend/`), `npm run build` (in `frontend/`), `python3 scripts/generate_third_party_licenses.py`; on Dependabot pull requests the workflow `dependabot-licenses.yml` does it |
| `.claude/` and `CLAUDE.md` | changing `AGENTS.md`, `.opencode/commands/` or `.opencode/agents/` | `python3 scripts/sync_agent_config.py` |
| `frontend/src/api/generated/` | changing `api/openapi.yaml` | `npm run generate:api` (runs before `dev`, `build`, `test` and `type-check`) |
| `docs/screens/SCR-*.png` | – | rendered by the workflow `screens.yml` after the merge, never by hand |

## Dependabot Pull Requests

Maven, npm, Docker and Compose updates get `THIRD-PARTY-LICENSES.md` regenerated by `dependabot-licenses.yml`, which commits the file to the Dependabot branch and starts the CI for the new commit. After that commit Dependabot no longer rebases the pull request by itself; if it conflicts with `main`, comment `@dependabot recreate`. A dependency with a license that ADR-043 does not allow fails the workflow, and nothing is committed.

## Known Workarounds

### Rootless Podman Instead of Docker

Testcontainers talks to the Docker-compatible socket of Podman:

```bash
systemctl --user enable --now podman.socket
export DOCKER_HOST=unix:///run/user/$(id -u)/podman/podman.sock
export TESTCONTAINERS_RYUK_DISABLED=true   # the Ryuk reaper does not run under rootless Podman
```

Without Ryuk, containers of an aborted test run are not removed automatically; `podman ps -a` shows leftovers. The backend tests share one PostgreSQL server per test JVM and clone a database per test class, so a run starts about 13 containers.

### SELinux Labels on Bind Mounts

On hosts with SELinux (Fedora, openSUSE, RHEL), a container sees a bind-mounted directory only with a label option. Use `:z` (shared label) for directories that several containers or the host keep using, for example `-v "$PWD:/work:z"`. `:Z` (private label) relabels the directory for one container and makes it unreadable for others, which breaks a running Vite or a second container on the same checkout. Relabeling fails on files owned by another user; mount a copy in that case.

### JDK 25 Without a System Package

If the distribution does not package JDK 25 yet, unpack a Temurin archive from <https://adoptium.net/temurin/releases/> and point `JAVA_HOME` to it for the Maven wrapper:

```bash
JAVA_HOME=/path/to/jdk-25 ./mvnw verify
```

### Story Tests Without System Libraries for Chromium

`npx playwright install --with-deps chromium` needs root for the system libraries. Without it, run the story tests in the Playwright image that matches the `playwright` version of `frontend/package-lock.json`:

```bash
podman run --rm -v "$PWD:/work:z" -w /work/frontend mcr.microsoft.com/playwright:v1.64.1-noble npm run test:stories
```

### git in Distrobox

In a Distrobox container without git, link the git binary of the host's Flatpak SDK as described in [AGENTS.md](../AGENTS.md#git-access-in-distrobox).
