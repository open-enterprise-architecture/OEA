# REQ-078: Embed Draw.io diagrams in the WYSIWYG editor

## Statement

The system MUST enable embedding Draw.io diagrams as a code block (`drawio`) in the WYSIWYG editor (Arc42, UC-09). The code block contains Draw.io XML (`<mxGraphModel>`); the system MUST render this XML as an SVG preview. Clicking the preview MUST open a modal with the draw.io editor; after saving in the editor, the XML in the code block is updated. When editing shape labels in the draw.io editor, the system MUST offer entity mention autocomplete via `[[` (plain text name as the result, REQ-070 BR-08). The draw.io viewer and editor MUST be served from within the instance (shipped locally) by default, isolated on a separate origin, and an external draw.io service MUST only be used if the operator configures it explicitly.

## Rationale

Arc42 documentation often contains structured diagrams that cannot be modeled well in either Mermaid or PlantUML: detailed component diagrams, deployment topologies, free-form sketches. Draw.io is the most widely used free diagramming tool (market leader in this niche, VS Code extension + Confluence app). Embedding it as a plugin enables solution architects (SH-04) and business analysts (SH-08) to embed existing Draw.io diagrams directly into the architecture documentation, without screenshot workarounds.

## Context

Draw.io (aka diagrams.net) is open source (Apache 2.0) and provides an embed API (`diagrams.net/js/viewer-static.min.js` for read-only rendering and `embed.diagrams.net` for editor embedding via the postMessage protocol). Both approaches work locally (no external server needed if the JS library is shipped along).

The XML format (`mxGraphModel`) is stable; OEA stores it raw in the `content` field of the WYSIWYG editor as a `drawio` code block — identical to the handling of `mermaid` and `plantuml` code blocks.

Security review SEC-18 (2026-10-13) and owner decision Q9: draw.io labels with `html=1` carry HTML in the `value` attribute, so a deny-list sanitizer is insufficient; an editor iframe with both `allow-scripts` and `allow-same-origin` on the application origin can remove its own sandbox; a postMessage bridge without origin check accepts messages from any window; `embed.diagrams.net` sends diagram content outside the instance. Version 0.2.0 addresses these points.

## Type-Specific Fields

### Code Block Format

In the `content` field of the Arc42MetaObject, a Draw.io diagram is stored as follows:

````markdown
```drawio
<mxGraphModel dx="1422" dy="762" grid="1" ...>
  <root>
    <mxCell id="0"/>
    <mxCell id="1" parent="0"/>
    <mxCell id="2" value="CRM-System" style="rounded=1;..." vertex="1" parent="1">
      <mxGeometry x="80" y="80" width="160" height="60" as="geometry"/>
    </mxCell>
    <mxCell id="3" value="SAP ERP" style="rounded=1;..." vertex="1" parent="1">
      <mxGeometry x="360" y="80" width="160" height="60" as="geometry"/>
    </mxCell>
    <mxCell id="4" value="sends data" style="edgeStyle=..." edge="1" source="2" target="3" parent="1">
      <mxGeometry relative="1" as="geometry"/>
    </mxCell>
  </root>
</mxGraphModel>
```
````

### Rendering Behavior

| State | Display |
|---|---|
| Read view | SVG rendering of the XML via draw.io viewer library; no interactive editor |
| Edit view | Preview SVG with "Open in Draw.io" button at the top right |
| Editor modal open | `iframe` with the locally shipped draw.io editor on a separate origin, connected via `postMessage` |
| After editor save | Modal closes; XML in the code block is replaced by the updated XML |
| No XML (empty block) | Placeholder "Add Draw.io diagram" with "Open" button |

### Entity Mention in the draw.io Editor

When the user edits a shape label in the draw.io editor and types `[[`:

- OEA integration (via draw.io embed API postMessage) intercepts the keyboard event
- Autocomplete dropdown appears above the draw.io modal
- Selection inserts the entity name as plain text into the shape label
- No ID link in the XML (BR-08 / BR-09)

The integration requires a small JavaScript bridge between the draw.io iframe and the TipTap editor.

### Security

- The `<mxGraphModel>` XML MUST be parsed without external entities or DTDs (REQ-184) and sanitized before rendering (BR-09)
- Sanitizing is allowlist-based (REQ-180): only known draw.io elements and attributes are kept; HTML inside `value` attributes (labels with `html=1`) is sanitized with the same allowlist as other user content
- The SVG generated by the viewer library MUST also be sanitized with an allowlist SVG profile (SVG can contain inline scripts and event handlers)
- The draw.io editor runs on a separate origin from the application (or in an iframe with `sandbox="allow-scripts"` only, never combined with `allow-same-origin` on the application origin) and under a Content Security Policy (REQ-180)
- The postMessage bridge MUST accept only messages whose `event.origin` equals the configured draw.io origin and whose payload matches the expected message schema
- Default `drawioEditorUrl` points to the locally shipped draw.io; no external service is contacted unless the operator configures it

## Acceptance Criteria

**AC1** (Rendering from read view):

- Given: Arc42 answer with `drawio` code block
- When: User opens the answer
- Then: Draw.io diagram rendered as SVG (not as XML text); correct shapes and connections visible

**AC2** (Open editor modal):

- Given: User is in edit mode of the Arc42 answer
- When: Click on "Open in Draw.io"
- Then: Modal opens with the full draw.io editor; existing XML is loaded; user can add, move and label shapes

**AC3** (Apply changes):

- When: User saves in the draw.io editor (Ctrl+S or Save button)
- Then: Modal closes; updated XML appears in the `drawio` code block; SVG preview is updated immediately

**AC4** (New empty diagram):

- When: User inserts an empty `drawio` code block and clicks "Open"
- Then: draw.io editor opens with an empty canvas; after saving, XML is in the block

**AC5** (Entity mention in shape label):

- When: User edits a shape label in the draw.io editor and types `[[CRM`
- Then: Autocomplete dropdown opens above the draw.io modal; after selection `CRM-System` is inserted as plain text into the shape label

**AC6** (Security — no XSS):

- Given: Draw.io XML with `<mxCell value="<script>alert(1)</script>"/>`
- When: Rendering
- Then: Script tag is removed or escaped; no JavaScript executed

**AC7** (Web portal read-only):

- When: User opens Arc42 documentation in the web portal
- Then: Draw.io diagram visible as SVG; no editor button; no postMessage bridge active

**AC8** (Offline-capable):

- Given: OEA instance without internet access and default configuration
- When: User opens an answer with a `drawio` block and opens the editor
- Then: SVG rendering and the draw.io editor work without any request to a host outside the instance

**AC9** (HTML labels):

- Given: Draw.io XML with a cell `style="html=1"` and `value="<svg onload=alert(1)>"` or `value="<img src=x onerror=alert(1)>"`
- When: the preview is rendered in the editor, the Electron client and the web portal
- Then: no script executes

**AC10** (postMessage origin):

- Given: the draw.io editor modal is open
- When: a message in the draw.io protocol format is posted to the application window from an origin other than the configured draw.io origin
- Then: the message is ignored and the code block is unchanged

## Verification Method

- [x] Method: test (Playwright E2E for AC1–AC5, AC7–AC10, XSS payload corpus for AC6/AC9) + manual security review
- [x] Pass criterion: SVG visible (no `<xml>` text); editor opens; XML correct after saving; no script execution

## Dependencies

- **Prerequisites**: REQ-068 (WYSIWYG editor exists); REQ-070 (`[[` trigger for entity mentions); REQ-180 (safe rendering, CSP); REQ-184 (safe XML parsing)
- **New library**: `draw.io-viewer-static.min.js` (Apache 2.0; shipped locally); draw.io editor shipped locally or as a self-hosted draw.io instance in the deployment
- **Configuration**: `drawioEditorUrl` in MetamodelConfiguration → default: the locally shipped/self-hosted draw.io; an external service such as `embed.diagrams.net` only if the operator sets it explicitly
- **Influences**: REQ-075 (platform independence): local draw.io instance as a Docker container

## Trade-offs

- draw.io online (`embed.diagrams.net`) would be easier to set up, but sends diagram content outside the instance and requires an internet connection — not used by default (owner decision Q9)
- Local draw.io (shipped or self-hosted via the `jgraph/drawio` Docker image) is fully offline, but adds a dependency to the deployment
- Solution: `drawioEditorUrl` remains configurable; default = local; operators may opt in to an external service explicitly

## Implementation Notes

- TipTap CodeBlock extension with language attribute `drawio`; language-specific rendering (other code blocks: syntax highlighting; `drawio`: SVG preview)
- draw.io embed protocol: `postMessage({action: 'load', xml: '...'})` → editor loads; react to `{event: 'save', xml: '...'}` → write XML into the TipTap document
- XML sanitizing: DOMParser → traversal → whitelist-based filtering; no `innerHTML` assignment without sanitizing
