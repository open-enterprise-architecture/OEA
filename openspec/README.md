# OpenSpec – Implementation Specs

OpenSpec ([openspec.dev](https://openspec.dev)) bridges the requirements artifacts and the code. It does **not** replace the existing documents (UC, REQ, US, ADR) but references them.

## Structure

```bash
openspec/
├── config.yaml            ← project context (stack, conventions) and rules per artifact
├── schemas/oea/           ← project-specific schema (fork of spec-driven)
│   ├── schema.yaml
│   └── templates/         ← proposal.md, spec.md, design.md, tasks.md
├── specs/                 ← implemented system behavior per capability (grows with every change)
└── changes/               ← changes in progress
    └── archive/           ← completed changes
```

## Workflow per Change

The commands exist for both supported agents. They are generated by `openspec init` / `openspec update` and must not be edited by hand.

| Step | Claude Code (`.claude/`) | OpenCode (`.opencode/`) | Result |
|---|---|---|---|
| Explore (optional) | `/opsx:explore` | `/opsx-explore` | – |
| Propose | `/opsx:propose "US-001 OIDC login"` | `/opsx-propose "US-001 OIDC login"` | `changes/<name>/` with proposal, specs, design, tasks |
| Implement | `/opsx:apply` | `/opsx-apply` | code, tests, checked-off tasks.md |
| Archive | `/opsx:archive` | `/opsx-archive` | delta specs merged into `specs/` |

Further commands: `/opsx:update` / `/opsx-update` (revise a change), `/opsx:sync` / `/opsx-sync` (sync delta specs without archiving).

## Conventions

- A change typically covers one user story or a small group of related stories of a sprint.
- Change name: `<us-id>-<short-name>`, e.g. `us-001-oidc-login`.
- Scenarios in the specs are derived from the acceptance criteria of the user stories.
- Tests are created within the change that implements the behavior, not ahead of it.
- Deviations from accepted ADRs require a new ADR first.
- Contract operations without implementation carry `x-oea-status: planned` and the 501 response `NotImplemented` in `api/openapi.yaml`; the change that implements an operation removes both in the same pull request (the backend does not start otherwise). Parameter and payload details of requirements and user stories are non-binding until that change aligns them, and its proposal lists the sections it realigns.
- On archive: set the US status to `realized` incl. implementation hash, extend `requirements/traceability.md`.
- All OpenSpec artifacts are written in English.

## Updating the Generated Agent Files

The OpenSpec CLI requires Node.js ≥ 20.19. After upgrading OpenSpec:

```bash
openspec update
```

This refreshes the commands and skills in `.claude/` and `.opencode/` together.
